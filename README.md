# 代办凭证束的核销差异与清算冻结

线下代办票、实际交付和采购对账。`fixtures/` 是可离线使用的合成原始资料，字段、时间和状态含义见 `DATA.md`。

## 本地检查

使用 Python 3.11，不需要安装第三方依赖。从项目根目录运行：

```sh
python3 -m unittest discover -s tests -v
```

`tests/test_fixtures.py` 覆盖源表结构及跨表引用；`tests/test_business.py` 覆盖核销、
留置、差额、报送回执与冻结的业务规则。

## 离线对账报告

```sh
python3 -m clearing.report
```

只读取 `fixtures/` 本地资料，不接银行或真实采购系统。

## 模块划分（`clearing/`）

- `facts.py`：按 `recorded` 顺序应用更正（后者覆盖前者，付款不回写），并按作废生效日
  剔除生效之后的使用；作废前发生的对应保留。
- `attribution.py`：以「交付 → 票」整数最大流计算每张票真实消耗的上下界。verified 给
  下界，possible 只给上界；无法唯一归属的交付列出候选票，同一交付单位最多核一次。
- `claims.py`：逐行申报核对。证实份额确认、possible 份额留置、超报/无交付/跨供应方争议
  分别定性；留置份额在交付维度占用，不能被另一张结算单领走。
- `settlement.py`：把更正区分为跨供应方争议、同一供应方科目变更、交付不存在三类；
  已结算、待核对、无人申领三桶分列，不合并成「剩余额度」；按 `terms` 形成差额申请。
- `transmissions.py`：整批 received 不等于逐行驳回；重复回执不重复计付；驳回只释放
  未付款份额并复核再送资格；等待回执期间发现归属不实则冻结未送审行，已送出份额不释放。
  支持 `board_at(日期)` 时点重放。
- `audit.py`：按采购点和服务类型给出真实利用率区间、候选凭证/争议/付款日期追溯，
  并回答现在可送哪部分、哪些在对方账上未定、哪些按差额复核。
